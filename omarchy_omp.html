MENTAL MODEL

Stop thinking “desktop.” Think “workspaces + geometry + focus.”

Omarchy is an opinionated Arch Linux setup built around Hyprland. Windows normally place themselves; you move focus, move windows, change layouts, and jump between workspaces. The mouse still works, but the system is intentionally designed so the keyboard is the fast path.

Super means the Windows / Command-style meta key. If you remember only one rescue key, remember Super + Space: it opens the Omarchy menu.

RULE

Customize your layer

Use files under ~/.config for your changes. Treat /usr/share/omarchy as Omarchy-owned defaults rather than your personal edit surface.

Practical rule: before editing a file by hand, see whether Super + Space → Setup already exposes it.
THE RIGHT MENTAL MODEL

Omarchy 4.x is agent-first — not an autonomous “AI OS.”

Quattro makes coding agents feel like a native part of the operating environment. Omarchy knows about agents, launches them, tracks their usage, gives them purpose-built terminal layouts, exposes system controls through a CLI, and ships an Omarchy-specific skill so agents can help configure the machine.

What it does not mean: there is not a single background AI constantly running your desktop or deciding what to do. You choose an agent and invoke it. The “agentic” part is that the surrounding OS is deliberately designed to be easy for that agent to operate.
FIRST-CLASS AGENTS

Major coding agents are pre-wired, but lazy-loaded

Omarchy installs tiny launcher stubs and fetches the actual tool the first time you invoke it. Current first-class commands include:

That makes OMP part of Omarchy's intended agent ecosystem rather than an unrelated add-on.

DEFAULT AGENT

Pick one once

omarchy default agent omp

Or use Super + Space → Setup → Defaults → Agent.

If the selected agent is not installed yet, Omarchy installs it.

LAUNCH

Your agent gets an OS-level shortcut

Launch default agentSuper + Shift + Ctrl + A
Run default agent inlinea

The hotkey opens the agent in its own terminal. The shell alias runs it in the current terminal.

AGENTIC EXECUTION

Send the OS a task from the shell

omarchy agent prompt "Review this project"

This launches the configured agent directly into the task. Omarchy's documentation explicitly says these launches use the agent's unattended / don't-stop-to-ask mode.

Treat this like handing someone a shell. Use a clean Git tree, review the diff, and prefer plan/review modes for risky system changes.
WHY QUATTRO FEELS “AGENTIC”

The desktop itself exposes handles an agent can use

omarchy CLIThemes, fonts, updates, screenshots, debugging, plugins, defaults, and other internal functions are exposed as commands instead of only GUI clicks.
Omarchy SkillA built-in agent skill explains how to customize Hyprland, the shell/bar, themes, and Omarchy configuration using supported mechanisms.
Quickshell + pluginsQuattro's shell is one IPC-scriptable process with a plugin architecture, giving both humans and tools a more coherent control surface.

This is the meaningful architectural change: an agent doesn't have to blindly automate GUI clicks for many system tasks. It can work through documented files, shell commands, and structured Omarchy interfaces.

AI-AWARE DEVELOPMENT LAYOUTS

Agents are baked into the terminal workflow

Omarchy ships tmux functions that construct development workspaces around an AI agent:

tdl omp

tdl [agent] creates an IDE-like layout with your editor, the selected AI agent, and a terminal.

tdl omp claude

Run two agents beside the editor when you want a second implementation/reviewer.

tsl 4 omp

tsl creates a grid of panes running the same command — effectively a primitive agent swarm.

MULTI-REPO

One layout per subdirectory

tdlm omp

Creates a development-layout window for each subdirectory, useful for a collection of services or related repos.

AGENTS PANEL

AI usage becomes desktop telemetry

Once Omarchy detects supported coding-agent use, an Agents icon appears in the top bar. The panel can show subscription/balance information and usage by day/model.

Current built-in coverage includes Claude Code, Codex, and Fireworks. The data is refreshed periodically and can be merged across machines through a synced folder.

LOCAL AI

Local models are part of the menu too

Install → AI includes local-model options such as LM Studio and Ollama, plus graphical AI apps.

This is convenience/integration, not a special Omarchy inference runtime.

SAFETY / RECOVERY

“Agent-friendly” also increases the blast radius

The official Omarchy AI docs call the Omarchy skill experimental and recommend using plan mode first for system customization. That is sensible: an agent that can edit dotfiles, execute shell commands, invoke Omarchy's own CLI, and run in auto-approval mode is much more useful — and can break much more, much faster.

CodeCommit or create a worktree before substantial agent changes.
System configKeep customizations in your user-owned config layer rather than editing packaged Omarchy files.
Agent changesPlan first, inspect commands/diffs, then execute. If config gets mangled, Omarchy provides config reinstall/recovery paths.
BOTTOM LINE

Why people are calling Omarchy 4.x “agentic”

It is not because the window manager suddenly contains an LLM. It is because the workstation has been reorganized so AI coding agents are peers of the editor, terminal, and shell rather than applications bolted on afterward. Agent launch, selection, usage, layouts, system control, configuration knowledge, and extensibility all have explicit first-class paths.

For someone already inclined to use OMP, Claude Code, Codex, OpenCode, or several of them side-by-side, that distinction is more important than an “AI desktop assistant” gimmick.

THE BIG ONE

Scrolling is still tiling.

Dwindle and scrolling are two ways to tile a workspace. Floating is a different mode where a window is taken out of the tile geometry and may overlap other windows.

DwindleKeep every tiled window visible. New windows recursively split the available space.
ScrollingKeep useful window widths. The row can extend beyond the monitor; focus/scroll moves across it.
FloatingA window overlaps the layout like a conventional desktop window. Toggle per-window with Super+T.

WHEN DWINDLE WINS

Use it when overview matters

  • Browser + terminal + small utility
  • You want everything visible at once
  • You open only a few windows per workspace
  • You like “dashboard” geometry
WHEN SCROLLING WINS

Use it when width matters

  • Editor + agent + test terminal + browser
  • You hate panes getting progressively narrower
  • You think left-to-right in a workflow
  • You want several “full-ish width” windows on one workspace

WHAT IT IS

Oh My Pi (omp): an agentic coding surface in the terminal

OMP is a fork of Pi aimed squarely at real coding work: terminal UI, sessions, model/provider routing, built-in tools, LSP integration, MCP, skills, extensions, subagents, and persistent history. The useful mental model is “an IDE-aware coding agent that happens to live in your terminal”, not “a chatbot in a shell.”

INSTALL

Bun is the upstream-recommended package route

bun install -g @oh-my-pi/pi-coding-agent

Other supported routes include the installer script, Homebrew, and mise. Once installed, the command is omp.

FIRST SETUP

Configure, authenticate, run in a repo

omp setup
cd ~/src/my-project omp

Inside a session, /login handles provider-scoped authentication and /model changes the active model.

SESSIONS

Continue

omp --continue

Continue the most recent session / terminal breadcrumb.

TREE ≠ RESUME

History has two levels

/tree navigates positions/branches inside the current session file.

/resume switches to a different session file.

/branch normally creates a new session from an earlier prompt.

This is worth learning early. It makes experiments cheap because you can rewind without throwing away the old path.
CONFIG LOCATIONS

Global vs project

~/.omp/agent/ — global agent data/config/auth/session base.

<project>/.omp/config.yml — project-specific settings.

omp config path
omp config list
PROVIDERS

Provider ≠ model

A provider is the backend/account namespace — e.g. Anthropic, OpenAI, Gemini, OpenRouter, Ollama. A model is selected under that provider, typically as provider/model-id.

OMP can also define custom OpenAI-compatible providers in ~/.omp/agent/models.yml.

A SENSIBLE FIRST HALF-HOUR

Omarchy + OMP together

Get the desktop navigation under your fingers.

Super + Space, Super + Return, Super + Arrow, Super + 1/2, Super + W. Don’t customize anything yet.

Make one workspace scrolling.

Go to workspace 2, press Super + L, then open terminal + browser + another terminal. Feel why scrolling is useful for development before deciding whether to make it your default.

Install/configure OMP.

bun install -g @oh-my-pi/pi-coding-agent omp setup

Start OMP from the repository root.

cd ~/src/project git status omp

Running from the right directory matters because OMP discovers project context and project-level configuration from there.

Learn exactly four OMP controls first.

/model, /tree, /resume, /compact. The rest can wait until you need them.

Then customize, one annoyance at a time.

Omarchy: edit your ~/.config/hypr/* overrides. OMP: edit global/project config or add MCP/skills only when the default workflow actually bumps into a limitation.

DON’T OVERENGINEER DAY ONE

Resist these urges

  • Rebinding every Omarchy key immediately
  • Turning every window into a float
  • Adding ten MCP servers before you need one
  • Creating elaborate OMP model routing before basic sessions feel natural
AGENT HYGIENE

Use the same discipline you would with a human developer

Start cleanKnow your branch and working-tree state before the agent touches files.
Ask for verificationTests, typecheck, lint, build, and a concise changed-files report beat “looks good.”
Branch experimentsGit branches/worktrees protect code; OMP session tree/branches protect reasoning history. Use both.

THE THREE CONFUSIONS TO AVOID
Easy to confuseCorrect mental model
Scrolling vs floatingScrolling is a workspace tiling algorithm. Floating is a window state.
/tree vs /resumeTree moves within one session file. Resume switches session files.
Provider vs modelProvider is the service/backend. Model is the specific model selected from it.
