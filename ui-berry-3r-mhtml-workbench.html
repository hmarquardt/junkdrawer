Feather banner removal bookmarklet

not yet tested

Every candidate tab renders inside a Feather proxy frame that draws a banner across the top. Remove it without opening Chrome DevTools, then inspect the real page.

★ Drag to Bookmarks Bar
1Show Chrome's bookmarks bar: ⌘⇧B (macOS) or Ctrl+Shift+B, or menu Bookmarks ▸ Show bookmarks bar.
2Drag the berry button above onto the bookmarks bar. Chrome saves it as a bookmarklet; it installs once and stays for every later task.
3In the candidate's own Chrome tab (opened with Open the environment in a new tab), click the bookmarklet. The banner disappears and the top spacing returns to what the page intends.
4Reuse it on any subsequent task — it is not tied to this archive.
Chrome restrictions and the console fallback

Chrome blocks javascript: URLs typed or pasted into the address bar, and blocks bookmarklets on pages that forbid script injection (a strict Content-Security-Policy, the Chrome Web Store, some viewers). Dragging onto the bookmarks bar is the supported path. If it refuses to run, open DevTools ▸ Console and paste the snippet below — that is the only situation where DevTools is needed.

Model provider
OpenRouter settings (optional)

      

    
The workbench works without a key: parsing, the Before/After diff, the feature matrix and every validation rule are deterministic and local. A key only adds optional AI passes that organize evidence. Final justifications are yours to write — nothing here generates them, and the workbench refuses to fill them from a model.

    

      
      
      
    

    

      
      
      
    

    
Keys and the selected model stay in this browser only, are never sent to archived content, and are stripped from every export and log. A key is checked as you type: leading and trailing spaces are trimmed, but the inside of a key must be plain ASCII — CJK characters, emoji, typographic quotes or a non-breaking space pasted in from a chat window are rejected with the exact position, never silently repaired, because an HTTP header can only carry ISO-8859-1 bytes. The catalogue endpoint is public, so loading the model list sends no key at all; a model counts as verified only after a real request with your key succeeds.
